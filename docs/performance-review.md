# 双端性能优化记录

本轮不改 Markdown 解析语义，不新增图片缓存容量接口，不启动例子应用。

## 已实现

- 双端主题相同值赋值不再触发重新解析/布局。iOS 主题提供 Equatable。
- 扩展语法处理中的固定正则编译一次复用。
- 未变表格保留单元格；比较主题、对齐、内容与格式，不仅比较纯文字。
  iOS 保存输入快照；Android 未识别的自定义 Span 保守重建。
  图片/公式单元格继续重建，避免跳过异步加载及其尺寸更新。
- iOS 示例由内容/尺寸通知驱动高度更新，合并到一个刷新周期；
  播放任务存在本身不再触发周期性列表布局。拖动期间推迟更新。
- 内存修复：iOS 图片等待期间不强持有附件，默认网络加载取消状态加锁；
  Android 临时离屏取消待渲染/图片任务，但不清空子视图，重新挂载时按需恢复。
  示例 Activity 销毁时 reset 所持有的 Markdown 视图并解绑 adapter。
  Mermaid 销毁幂等，忽略销毁后的异步回调。

## 第二批：解析、段落更新、公式请求

- 首版只复用普通段落；现已由下述第三批通用块级增量解析替代。
- Android 无格式正文保留 Editable 缓冲，只替换变化尾部；带格式或附件的内容保守重新绑定。
  iOS 无复制块/旧附件的正文通过 NSTextStorage 替换变化尾部，保留属性也一致的完整段落前缀。
- 双端相同公式、字号、颜色、像素密度的并发请求共用一次渲染；取消一个订阅不影响其他订阅。
  无订阅的底层请求保留至完成或 10 秒超时，允许流式重新绑定加入。
 最多 64 个不同请求、256 个活跃订阅，防止无界积压。

## 第三批：通用块级增量解析

- iOS 继续只使用 swift-markdown，Android 继续使用 commonmark-java；没有新增解析器。
- 使用解析器给出的顶层块位置建立稳定前缀，不再以空行猜测块边界。
  列表、引用、表格、标题、围栏/缩进代码、HTML 等块都可随文档推进进入复用前缀。
- 尾部两个顶层块始终一起重解析：最后的残缺行可能变成列表项，合并进前一个列表；
  容器内部、未结束围栏不会被切开。单个很长的列表/引用/代码块仍会整体重解析。
- 扩展预处理在全文上执行，缓存针对预处理后的文本；若公式闭合等操作改写缓存前缀，
  清空缓存并全量重解析。历史编辑、截短及 reset 同样不会复用不匹配的语法树。
- 出现链接定义特征 `]:` 或脚注特征 `[^` 时保守全量解析，包含转义/跨行标签；
  即使这些字符出现在代码等字面量中也可能回退。这避免定义表和脚注编号的全局依赖失效。
  普通行内链接、图片和完成的公式不再一律禁用增量。
- 仍需全文预处理、前缀检查和语法树到富文本的遍历；并非整个流水线的常数时间更新。
  此次不改对外 API，不改图片缓存，不启动应用，不宣称未经测量的提速比例。

公式缓存配置见 README。图片加载/缓存继续由业务已有注入接口控制。

## 验证边界

- 第二批 Android 库测试实际运行：91 项全部通过。覆盖主题去重、表格复用/格式变化、
  临时离屏恢复、逐分片增量与全量输出对比、正文缓冲复用、公式合并及取消隔离。
- 首批遗留的两个测试失败已修复：表格宽度使用原生图形测量，保留精确宽度断言；
  图片测试补齐 TextView 布局参数，避免异步重新绑定时抛异常，使用真实行数、
  高度变化验证换行，而非要求 Layout 对象必须换实例。图片生产代码无需改动。
- 第三批新增 P0～P3 全部用例按分片与全量解析对照，包含表格、格式、复制范围、图表；
  另有逐字符歧义边界、历史修改/截短/reset、实际复用长度及全量回退验证。
  Android 还覆盖固定种子的 40 组混合块及随机分片大小；最终库测试 95 项全部通过。
- 首批 iOS 库及示例编译检查通过；第二、三批库和测试源码编译检查通过。
  未执行 iOS XCTest 或界面验收。
- 尚无 CPU/帧率/内存曲线测量，因此不宣称具体提速比例或“零泄漏”。

## 后续独立优化

- Android 富文本段落、复制按钮的进一步差量更新。
- 消息 ID 索引，减少长会话分片的线性查找。
- 定义依赖的精细失效、长容器内部的增量解析，以及扩展预处理/富文本生成的进一步优化。

建议运行时验收：长消息播放、表格后追加正文、图片加载后高度变化、主题修改、
快速来回滚动、进入/退出含 Mermaid 页面，比较布局次数及页面释放情况。
