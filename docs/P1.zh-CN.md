# P1：CommonMark / GFM 用例与验收

## 状态与范围

已建立 60 个共享用例并接入双端示例和回归测试入口；**尚未执行构建、测试或双端 UI 验收，不代表全部通过或完整兼容规范**。P0 的 18 个用例及默认测试入口保留不变。示例选择菜单按 P0、P1 顺序展示，共 78 项。

唯一数据源为 [p1.json](../ios/Fixtures/data/p1.json)。Android assets、iOS Swift Package 资源和 CocoaPods 测试资源均引用该目录，不维护平台副本。

语法目标参考 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) 与 [GFM](https://github.github.com/gfm/)。颜色、字号、链接下划线、引用间距和复制按钮布局是项目主题/交互约定，不是 Markdown 规范规定的视觉值。

本批覆盖主要正常写法及边界，不是规范的完整测试集。裸 URL 自动链接、复杂定界符组合等仍可后续补充；原始 HTML 仅安全文本降级。数学、脚注、提示块、语法高亮属于 P3，视频不在本次范围内。窄屏、大字体、长内容等专项属于 P2。

## 数据约定与自动检查

每项包含原文、固定分片、文本/复制/表格数量预期及人工验收说明。分片以源行为基础，再按最多 8 个 Unicode 码点拆分，保留全部空白及 CRLF；拼接结果必须逐字等于原文。短分片会覆盖部分未闭合标记、未完成引用定义和表格分隔行。

- 加载器检查 schema、重复 ID 和原文/分片一致性。
- 两端共享契约测试遍历每个分片，检查复制范围、最终文本、表格/图表数量及固定复制内容。
- Android 通过实际流式缓冲逐片刷新；iOS 契约测试直接渲染每个累积前缀。
- 完成态与一次性全文渲染的文本/分段结果比较。该比较不证明视觉属性或滚动行为正确。
- 自动契约不会替代粗斜体、缩进、链接点击、图片加载、对齐和间距的人工验收。测试入口已接入，当前未运行。

## 建议验收顺序

1. 在用例菜单选择 P1-01，依编号检查“全文”。
2. 点击状态说明行，对照原文和验收要求；不要只与另一端互相比较，因为两端可能同时出错。
3. 对强调、代码、引用定义及表格用例再执行“播放 / 暂停 / 单步”，完成后与“全文”对照。
4. 复制应检查剪贴板内容；链接和图片检查回调地址。示例图片使用本地 mock，不依赖网络。
5. 反馈格式：用例 ID、平台（iOS 请注明 SPM 或 CocoaPods）、全文或第几个分片、主题/字号、截图及观察。发现问题后逐项修复、单独本地提交。

初次验收使用默认主题和默认字号；自定义主题允许更改视觉值，但不能破坏语义与布局。软换行统一为空格，两个行尾空格或反斜杠是硬换行。表头加粗，正文仅在语法指定时加粗。任务框目前仅展示、不交互。
